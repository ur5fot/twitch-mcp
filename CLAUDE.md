# twitch-mcp

Локальный read-only MCP-сервер для контекста Twitch-канала (Helix): инфо о
канале, статус эфира, свежие видео, расписание. Полное описание — `README.md`
(канон).

**Как переехал сюда:** `hub/docs/plans/*-mcp-tools-relocation.md`.

## Статус

Кредов нет: `TWITCH_CLIENT_ID` и `TWITCH_ACCESS_TOKEN` пустые, блокер внешний —
Twitch Developer Console требует 2FA на аккаунте, создающем приложение. Пока
кредов нет, инстанс **не зарегистрирован** ни в Claude Code, ни в Codex. Код
живой и покрыт тестами; регистрация — один шаг после появления ключей.

## Жёсткие правила

- **Инструмент ничего не знает про аккаунт.** Дефолтного логина в коде нет:
  логин приходит аргументом либо из `TWITCH_CHANNEL_LOGIN` (алиас
  `TWITCH_BROADCASTER_LOGIN`) env-файла проекта-владельца (`--env-file`).
  Соседний `.env` сервер не читает. Реальных логинов не должно быть ни в
  README, ни в `.env.example`, ни в **тестовых фикстурах**.
- **Без логина — ошибка инструмента, а не тихий поход в чужой канал.**
  Аргумент имеет приоритет над env, регистр приводится к нижнему.
- **Read-only и точка.** Нет сообщений в чат, модерации, клипов, рейдов,
  опросов и предсказаний. Запись добавлять только за confirm-токенами и с
  явными OAuth-скоупами.
- Client id и токен не печатать никогда; `twitch_validate_token` отвечает
  фактом валидности, а не содержимым токена.
- Наверх отдаются очищенные поля, не сырые объекты Helix.

## Проверка

```bash
npm test                                     # node --test
node src/server.js                            # + tools/list по stdio
```

Живой проверки Helix нет до появления кредов, но старт сервера и `tools/list`
проверять обязательно: это ловит поломку импортов без обращения к сети.
